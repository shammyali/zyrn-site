01Why this exists

Banks have run on Oracle and COBOL for forty years. They don't switch. Not because the software is good — because the math is reliable.

1 + 1 = 2. Every time. No exceptions. No hallucination. No vector-similarity approximation. The database returns truth, the application trusts it, the regulator accepts it.

Then AI showed up. People started bolting LLMs onto SQL databases. The LLM forgets things, invents things, confuses sources. Vector search guesses what's relevant. Knowledge graphs pretend the underlying data is clean. RAG calls hallucination a feature.

None of that is acceptable for a real business system. If Mnemos — sorry, Zyrn — fails on structured deterministic correctness, it's just another doc dump where AI invents answers.

Zyrn is built so that AI can be the operator of the database without being able to lie about what's in it. Every fact carries provenance. Nothing mutates. Aggregates ship with derived_from arrays naming the exact source facts. Vectors are rankers, never truth.

02What's different

Most "AI databases" are an old database with one new feature bolted on.

systemshapeai posture
SQL + vector extension row tables, vector column LLM writes SQL it doesn't fully understand
Document DB + embeddings flexible JSON, vector index RAG decides truth by similarity
Knowledge graph + LLM RDF triples, SPARQL schema brittleness, no provenance
Lakehouse + ML columnar files analytics-shaped, not transactional
zyrn typed facts, append-only, content-hashed AI calls typed tools; never SQL; provenance mandatory

Zyrn collapses structured rows, unstructured documents, conversation memory, and document extractions into one primitive: source-backed typed facts. Same retrieval model, same audit trail, same determinism guarantee. The AI doesn't choose between "ask the DB" or "ask the documents." Everything is a fact.

03The 7 invariants

These are theorems, not features. Each has code, tests, and audit paths behind it. Together they are the bank-grade contract.

INVARIANT 1

Sequence gap-freedom

next_sequence_value("invoice") returns 1, 2, 3 … forever. No gaps. No duplicates. Even under crash. Even under 1000 concurrent callers.

INVARIANT 2

Multi-fact atomicity

append_facts_atomic([a,b,c]) — all three land or none. No partial state visible to any reader, including a reader 1µs after SIGKILL.

INVARIANT 3

Content-hash determinism

Same logical fact → same SHA-256, byte-for-byte, across machines, OS, locale, JSON library version. Canonical JSON spec, not serde whim.

INVARIANT 4

Idempotency contract

append_with_idempotency_key("k", fact) — same key always returns same fact. Retry-safe forever. No TTL ambiguity.

INVARIANT 5

Bi-temporal replay

Query::known_at(T) returns the exact same answer today, tomorrow, ten years from now. Pure function of (T, fact_state_at_T).

INVARIANT 6

Supersession ordering

If F2 supersedes F1, every reader sees F2-shadows-F1. No window where both look current.

INVARIANT 7

Cross-replica consistency

CP mode: acks are durable on quorum. AP mode: convergence is deterministic per spec'd conflict rules. No "eventual" with eyes closed.

04Install

One-line install, Docker, or build from source. Pick what fits.

One-liner (Linux + macOS, x86_64 + aarch64)

# Installs zyrn binary to ~/.local/bin
curl -fsSL https://raw.githubusercontent.com/shammyali/zyrn/main/install.sh | bash

Docker

docker run -p 7878:7878 -v $PWD/data:/data \
  -e ZYRN_AUTH_TOKEN=$(openssl rand -hex 32) \
  ghcr.io/shammyali/zyrn:latest

Cargo install (build from source)

cargo install --git https://github.com/shammyali/zyrn --features http_server

Quick start

# 1. Generate a bearer token
export ZYRN_AUTH_TOKEN=$(openssl rand -hex 32)

# 2. Start the server
zyrn serve ~/zyrn.duckdb 127.0.0.1:7878

# 3. Probe
curl -s http://127.0.0.1:7878/health
# → {"status":"ok","version":"3.0.0"}

# 4. Verify integrity any time
zyrn verify ~/zyrn.duckdb
Auth is on by default. The server refuses to start without ZYRN_AUTH_TOKEN unless you pass --insecure (loud warning). For production, set the token via a secret manager — see SECRETS.md.

05Architecture

Single Rust binary. DuckDB columnar substrate. HTTP/MCP server with typed tool calls. No SQL surface for AI. Append-only fact log.

fact

Atomic unit. UUID, fact_type, schema_version, fields (JSON), source_path, source_hash, parser_id, content_hash, ingest_ts, supersedes, valid_from, valid_until.

typed tools

21 MCP tool calls. append_fact, retrieve, retrieve_head, aggregate, trace, relate, traverse, list_fact_types, describe_fact_type, verify, and more.

provenance

Every fact carries source. Every aggregate carries derived_from. Every supersede carries the parent. The audit chain is the data.

bi-temporal

System-time (when ingested) + valid-time (when true in the world). Query::known_at(T) replays history deterministically.

sharding

ShardedStore — one DuckDB file per tenant. Each shard preserves all 7 invariants. N tenants = N parallel writers.

vectors

BM25 + dense embedding + RRF, gated by Query predicates. Vectors are rankers, not truth.

07For AI agents

You may be an AI reading this to decide how to use Zyrn. Here's the contract.

  • You call typed tools, never SQL. Start with tools/list via MCP JSON-RPC. The server returns 21 tools with full JSON Schema.
  • Every fact you append must carry provenance. source_path, source_hash, and parser_id are mandatory. The server rejects facts that lack them.
  • You never invent facts. If you don't have a source, you don't have a fact. You may produce interpretations over facts — labeled as such.
  • The substrate refuses to forget. Corrections supersede; the old fact stays in the audit timeline. retrieve_head shows current state; retrieve shows everything; trace walks the chain.
  • Aggregates carry derived_from. Sum, count, avg — every result names the exact fact UUIDs that produced it. You can prove your number.
  • Vector ranking is for ordering candidates, not deciding truth. If the right fact is not in the candidate set, embeddings can't conjure it.
